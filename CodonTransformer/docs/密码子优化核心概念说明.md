# CodonTransformer 密码子优化核心概念说明

> 适用对象：`CodonTransformer/codontransformer_app.py` 调试界面。
>
> 本文解释“宿主”“解码模式”“强制同义约束”和采样参数的含义。完整操作步骤请参阅同目录的《演示界面使用手册》。

## 先建立一个整体认识

这个界面的输入是目标蛋白序列，输出是能编码该蛋白的 CDS（DNA 写法，以及将 `T` 替换成 `U` 的 RNA 写法）。

模型会结合两类输入：

1. 整条目标蛋白序列；
2. 指定的宿主物种。

对蛋白中每个氨基酸位置，模型会给不同 DNA 密码子一个分数（logit）。**解码**就是把这些分数转换为实际选用的密码子，进而拼成一条 CDS。

> 这里的“解码”不是解读遗传密码，也不是把 DNA 翻译成蛋白；它是从模型的“密码子概率分布”中选出一条具体 DNA 序列。

当前 CodonTransformer 基于 BigBird Masked Language Model：先针对整条输入计算各位置的密码子分数，再选择密码子；并非普通的、从 5' 端到 3' 端逐个自回归输出的解码器。

## 1. 宿主（organism）是什么

这里的宿主是**预期使用该 CDS 进行翻译的物种**。它告诉模型应采用该物种学习到的天然密码子使用偏好与序列上下文模式。

同一段蛋白在不同宿主下仍编码同一组氨基酸，但每个氨基酸可选择的同义密码子不同。因此更换宿主通常会改变：

- 生成的 DNA/RNA 序列；
- 各密码子的使用比例；
- GC 含量和局部序列组成。

### 如何选择

| 实际翻译场景 | 通常应选的宿主 |
|---|---|
| mRNA 最终在人体细胞内翻译 | `Homo sapiens` |
| 重组蛋白由大肠杆菌细胞表达 | `Escherichia coli general` |
| 其他生物体内表达 | 选择与目标翻译物种相符的选项 |

不要把“宿主”误当为质粒克隆或保存所用的细菌。例如，mRNA 最终要在人类细胞中翻译，即使质粒会先在大肠杆菌内扩增，也应选择 `Homo sapiens`。

### 能力边界

界面提供的是 164 个物种层级的条件，而不是细胞类型、组织、疾病状态或递送系统条件。因此选择 `Homo sapiens` 不等于针对某个具体人类细胞系完成优化，也不保证表达量、稳定性或免疫原性最优。

## 2. 解码模式

### 确定性（最优单条）

确定性模式在每个位置都选择模型分数最高的密码子（argmax）。在模型、输入和宿主相同的情况下，它通常给出同一条 CDS。

适用于：

- 需要一条可复现的基线序列；
- 想快速得到单一候选；
- 对比不同宿主条件的输出差异。

### 采样（多条变体）

采样模式不总是选择最高分密码子，而是按模型计算出的概率随机抽取。多次采样可得到多条不同的 CDS；在开启强制同义约束时，它们应翻译为同一条目标蛋白。

适用于：

- 观察同义密码子设计空间；
- 获得多个候选，供后续 GC、结构、motif 或其他评分器筛选；
- 展示同一蛋白的 CDS 并不唯一。

### 当前界面的重要实现细节

即使在界面中选择“采样（多条变体）”，右侧的“优化 DNA”“RNA 版本”和概览仍先显示一条**确定性**结果。采样只会额外生成下方“同义变体”表。

因此，调整 `temperature`、`top_p` 或 `num_sequences`：

- **不会改变**主结果区的那条优化 DNA/RNA；
- **只会改变**同义变体表中的采样序列及其数量。

## 3. 强制同义约束（`match_protein`）

绝大多数氨基酸有多个同义密码子。例如，亮氨酸可由六种密码子编码。密码子不同会改变 DNA/RNA 序列，但不改变翻译产物。

勾选 `match_protein` 后，界面会将不编码当前位置目标氨基酸的所有密码子分数设为 `-∞`。这样解码时只能从正确的同义密码子中选择，形成蛋白序列一致的硬约束。

| 设置 | 可能结果 |
|---|---|
| 开启（推荐） | 只在同义密码子空间内选择；输出应翻译回输入蛋白 |
| 关闭 | 模型仍会参考输入蛋白，但不再被禁止选择错误密码子；可能出现错义替换或提前终止，界面的“翻译一致”可能显示 ❌ |

对于“目标蛋白不变”的密码子优化，必须保持开启。若需要更丰富的候选，应提高采样多样性，但仍在同义约束下探索，而不是关闭该约束。

## 4. 采样参数

以下三个参数仅在“采样（多条变体）”模式的变体表中生效。

| 参数 | 当前界面范围与默认值 | 含义 | 调低的结果 | 调高的结果 |
|---|---|---|---|---|
| `temperature` | 0.1–0.9，默认 0.5 | 概率分布的随机性 | 更偏向最高分密码子，候选更保守，重复更可能出现 | 分布更平坦，候选更多样，但更可能出现不理想的局部特征 |
| `top_p` | 0.5–1.0，默认 0.95 | 核采样阈值；只从累计概率达到该阈值的高概率候选集合中抽样 | 可选密码子更少，输出更集中 | 可选范围更大；`1.0` 表示不截断低概率尾部 |
| `num_sequences` | 1–5，默认 3 | 独立采样的变体条数 | 候选较少、查看更快 | 候选更多，方便后续筛选；可能有重复条目 |

### 参数如何共同作用

采样时，模型先计算密码子概率，随后：

1. `temperature` 调整概率分布的尖锐程度；
2. `top_p` 移除累计概率尾部的低概率候选；
3. 从剩余候选中随机抽取密码子；
4. 重复该过程，得到 `num_sequences` 条变体。

低 `temperature` 加低 `top_p` 会使采样非常接近确定性选择，容易产生重复变体。高 `temperature` 加高 `top_p` 会扩大搜索范围，但“更多样”不代表“更好”。

在开启同义约束的前提下，随机性只会改变同义密码子选择，不应改变蛋白本身；但仍可能改变 GC、重复序列、二级结构、motif 和可制造性相关特征。

## 5. 推荐设置

| 目标 | 推荐配置 |
|---|---|
| 获得一条稳定、可复现的基线 | 确定性；`match_protein` 开启 |
| 查看少量合理同义变体 | 采样；`temperature=0.5`、`top_p=0.95`、`num_sequences=3`；`match_protein` 开启 |
| 扩大候选搜索空间 | 采样；可尝试 `temperature=0.6–0.8`、`top_p=0.95–1.0`、`num_sequences=5`；`match_protein` 仍开启 |

不要把较高的随机性理解成自动获得更好的序列。当前界面显示的是模型生成结果、GC 含量和翻译一致性；它尚未实现针对表达、稳定性、免疫原性、RNA 结构、限制性位点或可制造性的完整多目标评分与硬约束筛选。

## 6. 使用前的最后检查

1. 宿主是否与实际**翻译**物种相符；
2. `match_protein` 是否保持勾选；
3. “翻译一致”是否为 ✅；
4. 若使用采样变体，是否已用后续评分与安全筛查筛选，而不是仅凭 GC 或模型概率决定。

> 本界面只生成 CDS，不生成 5'UTR、3'UTR 或 poly(A)。用于真实合成或应用前，必须纳入项目规定的序列安全筛查与完整多目标评估流程。
