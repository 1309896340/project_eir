# ViralRecon 演示 · 环境安装交接清单（真实流程）

> 按约定，大体积 / 需外网的下载与安装由你亲自执行。以下用于在
> WSL2 Ubuntu + Docker 中运行**真实** nf-core/viralrecon 流程；
> 本仓库 `src/viralrecon/` 的演示 app 为自包含模拟，**不依赖**本清单。
> 本机已确认：Windows + Docker Desktop 28.5.1 + WSL Ubuntu（缺 Nextflow）。

## ① WSL Ubuntu 内安装 Java 17 + Nextflow（约 200MB，首次运行另拉 ~150MB jar）

```bash
sudo apt update && sudo apt install -y openjdk-17-jre-headless curl
java -version                      # 应显示 17.x

curl -s https://get.nextflow.io | bash
mkdir -p ~/.local/bin && mv nextflow ~/.local/bin/
echo 'export PATH=$HOME/.local/bin:$PATH' >> ~/.bashrc && source ~/.bashrc
nextflow -version                  # 验证
```

- Nextflow 首次运行会从 GitHub releases 下载 nextflow-dist jar（缓存于 `~/.nextflow/`）。
- GitHub 访问慢时先配置代理：`export HTTPS_PROXY=http://<宿主机IP>:<端口>`。

## ② 启用 Docker Desktop 的 WSL 集成

Docker Desktop → Settings → Resources → WSL Integration → 打开 Ubuntu 开关
→ Apply & Restart。WSL 内验证：

```bash
docker run --rm hello-world        # 输出 Hello from Docker! 即成功
```

## ③ 运行 viralrecon 官方测试流程

```bash
mkdir -p ~/viralrecon-demo && cd ~/viralrecon-demo
nextflow run nf-core/viralrecon -profile test,docker --outdir ./results
```

- 首次运行自动完成：拉取 pipeline 代码（GitHub）→ 下载测试数据
  （nf-core/test-datasets，SARS-CoV-2 公开数据子集，几百 MB）→ 逐进程
  拉取 Docker 镜像（**共约 5~10 GB**：fastqc/cutadapt/bowtie2/ivar/
  samtools/multiqc 等全套容器）。
- 预留 ≥15GB 磁盘；网络正常时全程 30~60 分钟。
- Docker Hub 拉取失败：Docker Desktop → Settings → Docker Engine 配置
  `registry-mirrors`（国内镜像加速），或为 Docker Desktop 配置代理。
- 重跑/续跑：加 `-resume` 可复用已完成进程的缓存（work/ 目录）。

## ④ 查看结果

- 结果目录按样本分层；总入口报告：
  `~/viralrecon-demo/results/multiqc/<样本>/multiqc_report.html`
- Windows 浏览器直接打开
  `\\wsl$\Ubuntu\home\<用户名>\viralrecon-demo\results\multiqc\...\multiqc_report.html`
- 报告内容与本演示 app 的模拟报告一一对应：FastQC 质量分布、bowtie2
  比对率、覆盖度/深度图、变异表摘要。
