# 数据集摘要说明

> 盘点本项目**已下载**的全部数据资产，分析其元数据与内部结构（结构分析基于各文件前几行样本 + 流式计数统计，未全量加载）。逐字段的完整定义见各数据自带说明文档（见文末索引）。
>
> 撰写日期：2026-09-29。重点关注 CoCoPUTs 与 GENCODE 两个数据集。

## 1. 数据资产总览

| 数据集 | 位置 | 文件数 | 合计大小 | 内容一句话 |
|---|---|---|---|---|
| CoCoPUTs (HIVE-CUTs) | `data/cocoputs/` | 4 原始 TSV + 1 去重 TSV | ≈ 1.04 GB | 119,196 条人类 RefSeq CDS 的密码子 / 二核苷酸 / 密码子对**组成统计**（只有计数，无序列） |
| GENCODE human v50 | `data/gencode/human/` | 3 个 gz 文件 | ≈ 263 MB（压缩后） | 人类基因注释与**真实序列**：382,428 条蛋白编码转录本（含 5'UTR/CDS/3'UTR 坐标）、对应蛋白序列、全基因组 GTF 注释 |

两者互补：CoCoPUTs 提供人类密码子使用的**先验统计**，GENCODE 提供训练所需的**天然 mRNA/蛋白序列**。

## 2. CoCoPUTs（重点一：组成统计）

### 2.1 来源与版本

- 来源：FDA DNAHIVE 的 CoCoPUTs（HIVE-CUTs 的持续更新版），<https://dnahive.fda.gov>。
- 物种：Homo sapiens（Taxid 9606），参考基因组 **GCF_000001405.39（GRCh38.p13）**，RefSeq 分区。
- 文件名前缀 `o537` 是 CoCoPUTs 下载库内部的物种文件编号，非 Taxid。
- 四份 TSV 覆盖**同一批** 119,196 条 CDS（20,239 个基因），**同记录、同行序**（Gene ID + Protein ID 逐行比对零错位），可按行号直接拼接特征。

### 2.2 四表共同结构（前 13 列完全一致）

| 列段 | 字段 | 说明 |
|---|---|---|
| 1–8 | 元数据 | `Gene ID`（symbol 或 `LOC*`）、`Protein ID`（`NP_` 人工审校 60,249 / `XP_` 预测 58,360 / `YP_` 线粒体 13，另有 574 行为空）、`Accession`（contig，`NC_*` 染色体 / `NT_*` scaffold / `NC_012920` 线粒体）、`Division`、`Assembly`、`Taxid`、`Species`、`Organelle`（genomic 119,183 / mitochondrion 13） |
| 9 | 计数总数 | 各表不同，见下 |
| 10–13 | `GC% / GC1% / GC2% / GC3%` | 四表逐行完全一致；GC3% 是同义优化自由度的关键指标 |

数据行行尾多一个制表符，解析会多出一个空列（pandas 中 `dropna(axis=1, how="all")` 即可）。

### 2.3 四表分述

| 文件 | 大小 | 列数 | 第 9 列 | 计数列 | 计数口径（已全表验证） |
|---|---|---|---|---|---|
| `o537-Human_CDS.tsv` | 29.5 MB | 77 | `# Codons` | 64 种密码子（DNA 大写） | 64 列之和 = # Codons，零例外；# Codons **含终止密码子** |
| `o537-Human_CDS_Dinuc.tsv` | 18.8 MB | 29 | `# Dinucleotides` | 16 种二核苷酸 | 总数恒等于 3×#Codons − 3（只数位置 1…3N−3 的相邻对） |
| `o537-Human_CDS_Junc_Dinuc.tsv` | 17.8 MB | 29 | `# Junction Dinucleotides` | 16 种二核苷酸 | 只数**密码子交界**（第 i 个密码子第 3 位 + 第 i+1 个第 1 位），总数恒等于 #Codons − 1 |
| `o537-Human_CDS_Bicod.tsv` | 944 MB（最大） | 4,110 | `# Codon Pairs` | 4,096 种密码子对（**小写** 6-mer，如 `tttttc` = ttt+ttc） | 相邻密码子对 (i, i+1) 计数，总数恒等于 #Codons − 1；终止密码子参与末位配对 |

三张低阶表存在精确推导关系：密码子前两位 = Dinuc 的一列；每个 bicodon 的第 3、4 位 = 一个 Junc 二核苷酸（Junc 表可由 Bicod 完全推导）。

### 2.4 去重表

- `deduplicated/o537-Human_CDS.primary_genomic_deduplicated.tsv`（27.8 MB，112,454 行数据）：由 `scripts/deduplicate_human_cds.py` 生成——仅保留 `Organelle == genomic` 且 `Accession` 为 `NC_*` 的行，每个 `(Gene ID, Protein ID)` 按源文件顺序保留首条（剔除 13 条线粒体 + 6,358 行 primary/alternate scaffold 重复 + NT_ scaffold 行）。**做全基因组级别密码子使用统计时应优先用此表**。

### 2.5 使用注意事项

1. **DNA 字母表（T）**：所有密码子/密码子对列基于 DNA；本项目统一 RNA（U），需 T↔U 转换。Bicod 列名还是**小写**。
2. **原始计数而非频率**：跨基因比较需除以总数归一化，或计算 RSCU / CAI 权重。
3. **(Gene ID, Protein ID) 不唯一**（原始表中 6,358 行重复）：聚合前先去重或改用三元组键。
4. **组成统计 ≠ 表达标签**：本数据集只有序列组成信息，与表达量/稳定性无对应关系，仅作先验分布与参考统计。
5. **防泄漏**：同一 Gene ID 的所有行必须进入同一数据划分。
6. **Bicod 表很大**（4,110 列 × 119,196 行）：读取时按需选列（`usecols`），避免整表载入内存。

## 3. GENCODE v50（重点二：序列与注释）

### 3.1 版本信息

GTF 头部注释（`##` 行）声明：evidence-based annotation of the human genome (GRCh38), **version 50（Ensembl 116）**，日期 2026-04-08。通过 `scripts/download_gencode.cmd` 断点续传下载，`MD5SUMS` 覆盖全部三个文件。

### 3.2 三个文件分述

| 文件 | 大小（压缩） | 记录数 | 内容 |
|---|---|---|---|
| `gencode.v50.pc_transcripts.fa.gz` | 124 MB | **382,428** 条 | 蛋白编码转录本完整核酸序列（含 5'UTR + CDS + 3'UTR，DNA 字母表），header 内嵌 UTR/CDS 坐标 |
| `gencode.v50.pc_translations.fa.gz` | 20.2 MB | **382,428** 条 | 上述转录本对应的蛋白序列（氨基酸），与转录本按 ENST 一一对应 |
| `gencode.v50.annotation.gtf.gz` | 119 MB | 5,078,384 exon 等 | **全 biotype**（含 lncRNA 等）基因注释，见下方特征统计 |

GTF 特征统计（流式计数，全 biotype）：exon 5,078,384 / CDS 3,210,731 / UTR 1,518,443 / **transcript 644,292 / gene 78,733** / start_codon 358,311 / stop_codon 353,665 / Selenocysteine 155。蛋白编码转录本（382,428）约占全部 transcript 的 59%。

### 3.3 FASTA header 格式（重要，可解析）

转录本（`pc_transcripts.fa.gz`）：

```text
>ENST00000641515.2|ENSG00000186092.7|OTTHUMG00000001094.4|OTTHUMT00000003223.4|OR4F5-201|OR4F5|2618|UTR5:1-60|CDS:61-1041|UTR3:1042-2618|
```

蛋白（`pc_translations.fa.gz`）：

```text
>ENSP00000493376.2|ENST00000641515.2|ENSG00000186092.7|OTTHUMG00000001094.4|OTTHUMT00000003223.4|OR4F5-201|OR4F5|326
```

| 字段 | 含义 | 用途 |
|---|---|---|
| ENST…（带版本号） | 转录本 ID | 两文件按此关联 |
| ENSG… | 基因 ID | 数据划分按基因分组防泄漏 |
| OTTHUMG/OTTHUMT | Gencode/match 转录本 ID | 少用 |
| `OR4F5-201` | 转录本名（symbol + isoform 编号） | — |
| `OR4F5` | 基因 symbol | 可与 CoCoPUTs 的 Gene ID 尝试对齐（注意两库 symbol 版本差异） |
| `2618` / `326` | 序列长度（转录本 nt / 蛋白 aa） | 长度过滤 |
| `UTR5:1-60\|CDS:61-1041\|UTR3:1042-2618` | **mRNA 三段坐标** | 直接切片出 5'UTR / CDS / 3'UTR——本项目 mRNA 设计（UTR 用单核苷酸 token、CDS 用密码子 token）的直接数据来源 |

GTF 第 9 列 attribute 含 `gene_id / transcript_id / gene_type / transcript_type / gene_name / level / tag`（`basic` 标签可筛官方代表转录本）等键值对。

### 3.4 使用注意事项

1. **ID 均带版本号**（`ENST00000641515.2`）：做键关联时注意统一去版本或保留版本的一致策略。
2. 转录本序列为 **DNA 字母表（T）**，项目统一 RNA 需转换。
3. `pc_transcripts` 是**剪切后序列**，CDS 坐标是相对转录本的坐标，不是基因组坐标；基因组坐标需查 GTF。
4. 蛋白序列 C 末端**不含** `*` 终止符（长度 326 = OR4F5 蛋白全长），做"翻译一致性校验"时注意 `*` 的处理。
5. 未下载（`download_gencode.cmd` 默认三件套之外）：基因组 FASTA、RefSeq ID 映射、lncRNA 负样本 FASTA、polyA 位点。需要时运行 `scripts/download_gencode.cmd all`。

## 4. 两个数据集的关系与配合

| 维度 | CoCoPUTs | GENCODE v50 |
|---|---|---|
| 注释库 | RefSeq（GRCh38.p13） | GENCODE/Ensembl 116（GRCh38） |
| 提供物 | 组成**统计**（密码子/二核苷酸/密码子对计数） | **序列**（转录本/蛋白）+ 基因组注释 |
| 基因覆盖 | 20,239 基因、119,196 CDS | 78,733 基因、644,292 转录本（pc 382,428） |
| 项目用途 | 人类密码子偏好先验、CAI/RSCU 参考、组成约束 | 预训练语料（mRNA 三段切片）、蛋白约束目标序列来源 |

典型配合：从 GENCODE 取目标蛋白（蛋白约束）与天然 CDS/UTR（预训练样本）；从 CoCoPUTs 去重表计算人类密码子使用分布，作为生成模型先验或评分参考。两库基因 symbol 可对齐但版本不同，跨库 join 需容错（symbol 冲突/缺失）。
